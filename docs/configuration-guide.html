PfVarX configuration guide

Version 1.0.0. Open the editor with ./pfvarx configure --gui from your study workspace. Choose settings from the actual laboratory protocol and intended output. Save the form to create input directories. When editing YAML directly, run ./pfvarx init after saving.

The editor shows project settings from config/config.yaml, quality settings from config/quality.yaml, and compute settings from config/compute.yaml. Values below use YAML names. null means leave an optional field unset. Relative paths are resolved from the workspace.

input_typeFASTQ, BAM, CRAMUse FASTQ for paired .fastq or .fastq.gz reads. study_metadataNo or Yes (false or true in YAML)Study Metadata. Yes: you supply a study table (tab-separated, with a sample_id column, for example country, latitude, longitude, collection_date, population), Input directories creates its folder, and Inputs Preparation merges it into the sample metadata, filling empty cells only and listing differences. No (default): no study metadata folder is created and the pipeline continues with the sample metadata built from the input files. Assay

SettingValues or exampleWhen to choose it
assay_designwgs, targeted_umi, targeted_no_umiSelects the processing branch. Use wgs for direct and selective (sWGA) whole-genome libraries, targeted_no_umi for amplicon or panel libraries without UMIs, and targeted_umi when reads carry UMIs or imported BAMs are UMI consensus reads. FASTQ and BAM entry work with every design. The technique label, amplification route, panel and library protocol of each library go in the sample manifest.
assay.library_cataloginputs/metadata/library_catalog.yaml or nullRequired for targeted designs. A YAML file listing panels (panel_id, panel_version, targets BED, primers or probes) and library protocols (library_protocol_id, adapters, UMI read structure and consensus settings). Manifest rows name their panel and protocol by these IDs.
assay.two_colour_chemistryfalse or trueEnable only for documented two-colour chemistry when poly-G trimming applies.
assay.platformILLUMINARecord the real sequencing platform. This field does not install additional assay support.

Reference

SettingValues or exampleWhen to choose it
reference.fastainputs/reference/Pf3D7.fastaUse the exact parasite assembly underlying the reads or existing alignment. Enter the full file path, including the filename. Relative paths start at the study workspace. If you give only a folder, PfVarX uses the one file in it whose content is a FASTA sequence; with none or several, validation asks for the full path.
reference.core_mask_bedinputs/reference/core_genome.bedThe accessible core of the genome: the Core regions of Miles et al. 2016, as used by MalariaGEN, not a gene list. Variants are called and depth QC is measured only inside it. Check contig names and coordinates against the FASTA. Enter the full file path, including the filename. Relative paths start at the study workspace. If you give only a folder, PfVarX uses the one file in it whose content is BED intervals; with none or several, validation asks for the full path.
reference.host_removalFalse or TrueHuman DNA removal, optional and eligible only for the wgs design (not available for targeted_no_umi or targeted_umi). True: each FASTQ read pair is aligned once to the parasite and human genomes together, and pairs whose best alignment is on the human genome are removed before duplicate marking and counted (host_fraction in sample QC). False (default): reads are aligned to the parasite genome only. True needs the Human genome reference and a bwa-mem2 index of the combined reference that you build on a machine with enough memory (./pfvarx prepare lists the steps). Not applied to BAM/CRAM input.

analyses.microhap_locioff, derived or catalogueChoose where microhaplotype loci come from. Off keeps biallelic SNVs for DA001 and DA004. Derived needs no panel file: each of your panel's target regions holding at least two PASS SNVs becomes one locus, and whole-genome runs use core-genome windows instead, so the coordinates are your own inputs and nothing is assumed about a published panel. Catalogue uses the file in microhap_panel and is the better choice when your panel publishes its own loci, because derived loci are specific to this run's panel or window length and compare only with cohorts defined the same way.
analyses.microhap_panelnull or inputs/metadata/microhap_panel.tsvGive your panel's microhaplotype loci to turn several biallelic sites into one multiallelic marker per locus, which DA001 and DA004 are built for. Null selects the shipped panel, which contains no loci, so those analyses keep using biallelic SNVs and record that they did. Each locus needs a genomic range or a gene identifier; set the file's status to MAINTAINER_VERIFIED once every locus is checked against the panel documentation and your reference release.
analyses.spatial_outcome_sourcenull or DA002For explicit DA007 choose DA002 and provide valid geographic and collection-date metadata. Auto resolves the source.

Worked examples

Direct WGS paired FASTQ on a small PC

Bootstrap with --final-output FO002 with the default FASTQ/WGS choices. In the form choose FASTQ, FO002, assay design wgs and Local; record amplification_route DIRECT (or SWGA) per library in the sample manifest. Set the matching FASTA and core BED. For an 8 GB PC, start with 6500 MiB total and per job, one job, and a thread count that fits your CPU.

Existing indexed alignment

Bootstrap with --final-output FO002 --input-type BAM or --input-type CRAM. Choose FO002. Register the alignment and index using the sample manifest, with its processing_state (wgs: aligned or duplicates_marked; targeted_no_umi: aligned or primers_trimmed; targeted_umi: aligned, consensus or consensus_primers_trimmed) so only the missing steps run. Use the same reference assembly used to align or encode it.

Targeted UMI sequencing

Bootstrap with --final-output FO002 --design targeted_umi. Choose FASTQ, FO002 and assay design targeted_umi, and point assay.library_catalog at the library catalog. In the catalog, define the panel (targets and primers) and the library protocol with both actual mate read structures. In the sample manifest, give each row its panel_id, panel_version and library_protocol_id; the optional technique label TBS_UMI or AMPLICON must match the design.

Automatic downstream analysis

Bootstrap with --final-output FO004 --auto-analyses and the actual design. Select FO004 and automatic analysis selection. Leave requested and scales empty. Supply matched annotation and an eligible catalogue for marker analysis. Add actual population, date and geography metadata where required. Review terminal reasons for excluded analyses.

Transfer raw data and run preflight

After saving, open Input files to upload reads (inputs/fastq/) or BAM/CRAM files (inputs/bam/) or download them using an HTTPS link and destination filename. Trusted SHA-256 is optional. When provided, PfVarX checks it before saving. Otherwise, PfVarX records the computed checksum and marks the download unverified. Put reference files in inputs/reference/.

Register the files before running Workflow Readiness Checks → Run readiness checks. The tab runs validate, prepare, verify-prepared, and ready in that order and stops on failure.
