0. Overview of the run

10. Targeted designs: library catalog, targets, primers

Set assay_design: targeted_no_umi or targeted_umi and assay.library_catalog: inputs/metadata/library_catalog.yaml (a template is written by init).

RecordWithout UMIWith UMI
Catalog panelpanel_id, panel_version, targets BED, primer TSV (or probes BED)Same

Manifest columnspanel_id, panel_version; optional technique (AMPLICON, TBS_NON_UMI)+ library_protocol_id; optional technique (AMPLICON, TBS_UMI)

Targets BED: zero-based, half-open. Primer TSV (fgbio TrimPrimers header):

chrom	left_start	left_end	right_start	right_end
Pf3D7_07_v3	403500	403520	403780	403800

Coordinates are one-based inclusive with 1 ≤ left_start ≤ left_end < right_start ≤ right_end ≤ contig length. A UMI structure must match the sequenced reads. A run uses one panel.

11. BAM / CRAM input

Set input_type: BAM or CRAM, put files in inputs/bam/ and record in processing_state what was already done. Only missing steps run.

DesignAllowed processing_state
wgsaligned, duplicates_marked
targeted_no_umialigned, primers_trimmed
targeted_umialigned (raw reads with RX UMIs), consensus, consensus_primers_trimmed

Requirements: coordinate-sorted, indexed, same reference dictionary/MD5, read group @RG SM equal to the sample_id. The state is checked against the reads (cD, RX tags) and @PG records; contradictions are rejected. CRAM is implemented but less validated than WGS BAM. VCF input is not supported.

12. Human DNA removal (optional, WGS FASTQ only)

Set reference.host_removal: true and reference.host_fasta: inputs/reference/GRCh38_no_alt.fasta. Each read pair is aligned once to parasite + human together; pairs whose best hit is human are removed before duplicate marking and counted as host_fraction.

You build the bwa-mem2 index of the combined reference yourself on a machine with enough memory for a human-sized genome../pfvarx prepare lists the exact steps and stops with HOST_INDEX_REQUIRED until the index files (combined.fasta.0123 .amb .ann .bwt.2bit.64 .pac) are in prepared/reference/.

13. Set the compute limits

Edit config/compute.yaml to match the machine. Shipped values:

schema_version: "pfvarx.compute/2"   # FIXED
executor: local                      # local | hpc | server | cloud (recorded only, one host)
max_cores: 4                         # total cores PfVarX may use
max_mem_mb: 6500                     # total RAM
max_jobs: 1                          # concurrent jobs
tmp_disk_mb: 20000
tmp_dir: null                        # absolute path for temporary files (e.g. node scratch)
per_job:
  max_threads: 4
  max_mem_mb: 6500
  max_runtime_min: 720
max_retries: 2                       # transient failures only
retry_memory_factor: 1.5

Rules: per-job limits ≤ totals; leave memory for the OS. bwa-mem2 alignment requests 6.5 GB, so max_mem_mb below that blocks the plan (RESOURCE_MEMORY_EXCEEDED). On HPC, submit the run inside one node allocation (all executors use a single host).

24. Report dashboard

xdg-open results/report/pfvarx_dashboard.html          # WSL2: explorer.exe results/report/pfvarx_dashboard.html

A single offline HTML file with eight pages: Overview (run identity, where results are saved, summary cards, run metadata), Inputs, Quality Control, Variants, Downstream Analyses, Resources, Software and Logs. Tables can be filtered and exported to CSV/XLSX; charts to PNG; print to PDF from the browser. View filters never recompute scientific estimates. report/clonality_report.txt states each sample as monoclonal or polyclonal with clone shares.

25. Resume, extend and rebuild the report

./pfvarx pipeline --mode RESUME --run-id RUN_ID     # continue an interrupted run (configuration unchanged)
./pfvarx pipeline --mode EXTEND --run-id RUN_ID     # new run reusing per-sample results, e.g. after adding analyses
./pfvarx report --run-id RUN_ID                     # redraw the dashboard only; nothing is re-analysed

Use a new run (--mode NEW) when reads, masks, primers, reference, scientific policy or preprocessing change.

26. Clean-up and archive

./pfvarx cleanup --run-id RUN_ID            # preview completed-run work files that may be removed
./pfvarx cleanup --run-id RUN_ID --apply    # remove only those
./pfvarx benchmark-resources --run-id RUN_ID   # optional: summarise measured resources
./pfvarx resources-learn --run-id RUN_ID       # optional: improve future time/memory estimates

Failed runs, inputs, references, final results, QC, logs and frozen records are always kept. Archive: the whole runs/RUN_ID/, config/, metadata/validation_report.json, prepared/samples.tsv, your input checksum file and the PfVarX version (./pfvarx version).

27. One-command chain

./pfvarx orchestrate                        # initialize → validate → prepare → verify → preflight → execute/report/retain
./pfvarx orchestrate --through validate     # stop after validation (also: prepare, verify)

Stops at the first failure. Use the separate commands above when you need to review each stage.
