Run PfVarX 1.0.0

First time? Getting started covers installing Pixi, installing and configuring PfVarX, and every step to the report, with a troubleshooting table.

This example uses paired-end WGS FASTQ for per-sample variant calls. The tools are installed on demand for the saved configuration (use bootstrap.py --final-output FO002 to install them up front on an offline machine). Use Linux x86-64, or the newly enabled experimental Linux ARM64/macOS 13+ targets (Intel or Apple silicon), with Python 3.11+ and Pixi on PATH. Windows uses WSL2 with supported Linux. See platform support for native CI qualification limits.

1. Download and install

Sign in to GitHub with access to the private repository. Run these commands from the parent directory. The clone creates PfVarX-source/, and bootstrap creates pfvarx-analysis/ beside it.

~/demo/
├── PfVarX-source/     # GitHub clone
└── pfvarx-analysis/   # study workspace
mkdir -p ~/demo
cd ~/demo
git clone https://github.com/hadish-bekuretsion1/PfVarX.git PfVarX-source
python3 PfVarX-source/bootstrap.py
cd pfvarx-analysis
./pfvarx version

2. Configure your study

Choose one configuration route. Set the actual reference release, FASTA, core-genome mask BED, assay and compute limits before creating the input folders. The core mask is the accessible core of the genome (the Core regions of Miles et al. 2016, as used by MalariaGEN), not a gene list. The sample profile defaults to FO002.

CLI configuration

nano config/config.yaml config/quality.yaml config/compute.yaml
./pfvarx init

Optional GUI configuration

./pfvarx configure --gui

Open the printed local URL if needed. Review the form and click Create Configuration and Input Directories. It creates only the folders you put input files into; set Study Metadata to Yes if you have a study table (country, latitude, longitude, collection_date, population, ...), and inputs/metadata/ is created for it. Then click Install required tools (./pfvarx install-tools): it installs only the tools the saved configuration needs.

Configuration guide for every setting

3. Transfer and register reads

After saving, open Input files to upload reads (inputs/fastq/) or BAM/CRAM files (inputs/bam/) or download them using an HTTPS link and destination filename. Trusted SHA-256 is optional. When provided, PfVarX checks it before saving. Otherwise, PfVarX records the computed checksum and marks the download unverified. Put reference files in inputs/reference/, and with Study Metadata: Yes your study table in inputs/metadata/.

Inputs Preparation → Prepare inputs (./pfvarx inputs-preparation) then builds the sample metadata prepared/samples.tsv from your input files, merges the study table into it if there is one, prepares the references and checks readiness. Workflow Readiness Checks → Run readiness checks runs prepare-samples, validate, prepare, verify-prepared and ready in that order and stops on failure.

Alternatively, register reads by hand: replace the example path with your FASTQ directory. Review sample identities, libraries and paired files before registration. Use a reviewed TSV manifest directly when the filenames do not match the discovery convention.

./pfvarx discover-inputs --directory /absolute/path/to/fastq
nano metadata/discovered_samples.tsv
./pfvarx register-inputs --manifest metadata/discovered_samples.tsv --mode reference

4. Validate and prepare

./pfvarx validate &&
./pfvarx inputs-preparation &&
./pfvarx dry-run

If validation fails, its summary names each problem, why it failed and the numbered steps that fix it; the full record is in metadata/validation_report.json. Resolve failures and review warnings before running. Confirm that readiness is true and the dry run reports OK.

5. Execute and review

./pfvarx pipeline --mode NEW

Record the returned run ID. Open results/report/pfvarx_dashboard.html and review sample QC before interpreting calls. FO002 results include sample VCFs under results/variants/samples/. Run logs and frozen configuration are under runs/RUN_ID/. If no sample passes QC, the run still completes and results/cohort/cohort_status.json explains which samples were blocked and why.
