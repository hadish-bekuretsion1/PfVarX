PfVarX configuration

Each tab runs the same step as its terminal command, shown on the tab. You can switch between this page and the terminal at any stage.

Terminal equivalent: edit the YAML files in config/, then ./pfvarx input-directories. A schema-3 configuration is migrated on save, as ./pfvarx config-migrate --apply does.

The path is relative to your study workspace. The folder is created when you save.

Input folders and expected contents

After saving, supply or register the files listed for your configuration.

    Inputs Preparation
    

    Terminal equivalent: ./pfvarx inputs-preparation (add --metadata-table PATH to choose the study table when the Study Metadata folder holds several).
    

    Every folder this step and the rest of the pipeline write is created when it is first needed; Input directories creates only the folders you put input files into.
    

      

    1. Sample metadata. Built from your input files as prepared/samples.tsv, with its folder: paired FASTQ names give the sample and lane IDs, and library_id defaults to sample_id, so review them. For BAM input a blank template is written for you to fill in. An existing file is never overwritten.
      2. 

    2. Study metadata. Study Metadata: Yes: the study table in the Study Metadata folder (tab-separated, with a sample_id column) is merged into the sample metadata; empty cells are filled, existing values are never overwritten and differences are listed. If the folder has no table yet, preparation continues with the sample metadata and says so. Study Metadata: No: preparation continues with the sample metadata only.
      3. 

    3. References. Built under prepared/reference/ for what your input files and final output need: the FASTA index and sequence dictionary always, and the BWA-MEM2 index when reads are aligned (FASTQ input, and UMI BAM input). Files that are already current are reused. The annotation database for FO004 is built from the GFF during the run.
      4. 

    4. Checks. The prepared files are verified and the workflow readiness is checked.
      5. 

    


    

    

    

    Workflow Readiness Checks
    

    Terminal equivalent: ./pfvarx workflow-readiness-checks.
    


    

    

    

    

    Workflow Check and Run
    

    Terminal equivalent: ./pfvarx workflow-check and ./pfvarx workflow-run.
    

    The check plans the workflow without creating outputs. The run repeats the check and, only if it passes, starts a new analysis. A run continues in the background if you close this page; reopen this tab to see its status.
